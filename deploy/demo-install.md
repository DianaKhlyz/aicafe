# Установка демо-сайта: полная инструкция

Три варианта — по возрастанию «серьёзности». Для показа заказчику
рекомендуется **вариант 2** (сервер с доменом): работает HTTPS, вебхук
Telegram-бота и доступ с любого телефона.

Демо работает целиком на мок-данных iiko (`AICAFE_IIKO_MOCK=true`,
включён по умолчанию) — ключи и интеграции не нужны.

---

## Вариант 1. Локально на ноутбуке (5 минут, без сервера)

Требования: Python 3.11+, [uv](https://docs.astral.sh/uv/), Node 20+.

```bash
git clone https://github.com/DianaKhlyz/aicafe.git && cd aicafe
make install          # зависимости бэка и фронта
make dev-backend      # терминал 1: FastAPI на :8000
make dev-frontend     # терминал 2: Vite на :5173
```

Сайт: `http://localhost:5173`.

Чтобы открыть **с телефона** (сайт mobile-first, показывать нужно с
телефона): ноутбук и телефон в одной Wi-Fi-сети, фронт запустить с
флагом `--host`:

```bash
cd frontend && npm run dev -- --host
```

и открыть на телефоне `http://<IP-ноутбука>:5173`.

Ограничение варианта: Telegram-бот смен работать не будет (Telegram
не может достучаться вебхуком до localhost). Всё остальное — работает.

## Вариант 2. Чистый VPS с доменом (рекомендуется, ~15 минут)

Требования: VPS Ubuntu 22.04/24.04 (1–2 ГБ RAM достаточно), root-доступ,
домен с A-записью на IP сервера (создать заранее — DNS должен успеть
обновиться).

```bash
ssh root@СЕРВЕР
git clone -b claude/cafe-site-architecture-3qpvau https://github.com/DianaKhlyz/aicafe.git /opt/aicafe
/opt/aicafe/deploy/setup.sh демо-домен.ru
```

Флаг `-b` важен: рабочая ветка проекта может не совпадать с веткой по
умолчанию на GitHub. Если уже клонировали без него и файлов нет —
`cd /opt/aicafe && git checkout claude/cafe-site-architecture-3qpvau`.

Скрипт сам ставит Node, uv и Caddy, создаёт системного пользователя,
собирает фронтенд, включает systemd-юнит и получает HTTPS-сертификат.
Повторный запуск безопасен. В конце печатает результат проверки
`/api/health` — должно быть `{"status":"ok","iiko_mode":"mock"}`.

Если на сервере включён файрвол — открыть порты:

```bash
ufw allow 80 && ufw allow 443
```

Сайт: `https://демо-домен.ru`.

## Вариант 3. Чистый VPS без домена (по IP, без HTTPS)

Тот же скрипт, но вместо домена передать `:80`:

```bash
/opt/aicafe/deploy/setup.sh :80
```

Сайт: `http://IP-сервера`. Финальная строка скрипта покажет адрес
криво («https://:80») — это косметика, не ошибка.

Ограничения: нет HTTPS (для демо приемлемо) и не работает вебхук
Telegram-бота (Telegram требует HTTPS) — бот смен показать не получится.

## Настройка после установки (варианты 2–3)

Конфиг: `/opt/aicafe/backend/.env` (создан из `.env.example`).
Для демо достаточно значений по умолчанию. Что можно включить сверх:

| Что | Переменные | Зачем |
|---|---|---|
| Уведомления персоналу в TG | `AICAFE_TELEGRAM_BOT_TOKEN`, `AICAFE_TELEGRAM_STAFF_CHAT_ID` | Живое демо «заказ упал в группу» |
| Бот смен (только вариант 2) | те же + `AICAFE_PUBLIC_BASE_URL=https://демо-домен.ru`, `AICAFE_TELEGRAM_WEBHOOK_SECRET=<любая строка>` | Полное демо смен |

Как получить токен и chat_id за 5 минут:

1. В Telegram открыть **@BotFather** → `/newbot` → имя → получить токен.
2. Создать группу «Кафе — смена» (или использовать существующую),
   добавить бота и назначить его **администратором** с правами
   «приглашать по ссылке» и «удалять участников».
3. В настройках группы включить «История чата видна новым участникам».
4. Написать любое сообщение в группу, затем выполнить:
   `curl "https://api.telegram.org/bot<ТОКЕН>/getUpdates"` — в ответе
   найти `"chat":{"id":-100...}` — это и есть chat_id.
5. Вписать значения в `.env` и перезапустить: `systemctl restart aicafe`.

## Эксплуатация демо

```bash
systemctl status aicafe        # состояние бэкенда
journalctl -u aicafe -f        # логи бэкенда (видны «отправленные» коды входа)
journalctl -u caddy -f         # логи веб-сервера
/opt/aicafe/deploy/update.sh   # обновить до свежей версии из git
systemctl restart aicafe       # перезапуск (сбрасывает счётчики мок-заказов —
                               # удобно делать перед показом, см. сценарии)
```

## Если что-то пошло не так

- **Caddy не получает сертификат** — DNS ещё не обновился (проверить:
  `dig +short демо-домен.ru` должен вернуть IP сервера) или закрыт 80/443.
- **`/api/health` не отвечает** — смотреть `journalctl -u aicafe -n 50`.
- **Порт 8000 занят** — на сервере уже что-то работает; демо рассчитано
  на чистый сервер.
- **Сайт открывается, меню пустое** — бэкенд не успел стартовать,
  обновить страницу; если не помогло — логи.

## Что дальше (после демо этот же сервер становится боевым)

Тот же сервер и та же установка доводятся до боевой без переустановки:
`AICAFE_IIKO_MOCK=false` + apiLogin (меню/заказы становятся реальными),
ключ DaData (боевые подсказки адресов), адаптер банка (реальная оплата),
`AICAFE_SESSION_SECRET` на случайную строку, Litestream для бэкапов
(см. [README.md](README.md)). Ничего из показанного на демо переделывать
не придётся — меняются только данные под капотом.
