## Зафиксированные решения (обсуждение 07.07.2026)

1. **Формат**: платформа универсальная, первый релиз — сценарий «кафе с
   доставкой».
2. **Эквайринг**: будет личный эквайринг банка владельца. Интерфейс
   `PaymentProvider` уже универсален — когда известен банк, пишется один
   файл-адаптер (создать платёж → редирект/QR СБП → вебхук). Заготовка ЮKassa
   остаётся как референс и запасной вариант.
3. **Доставка**: через агрегатора (~99%), своя — не раньше чем сильно позже.
   Карту курьера и iikoDeliveryman не делаем; трекер оставляем для статусов
   кухни/самовывоза («готов — можно забирать», «передан в доставку»).
4. **Хостинг**: VPS в РФ, ориентир — Fornex.
5. **Фичи**: автостоп-лист и Wallet-карты — обязательно; отзывы — да;
   QR-заказ за столом — да; предзаказ ко времени с умными слотами — да;
   подписки — заложить структуру, включать по решению; курьерский трекинг — нет.

   iiko через готовые интеграции, сайт фокусируется на самовывозе и предзаказе;
   или (б) заказ принимает наш сайт, а курьера вызываем по API логистического
   агрегатора (Яндекс Доставка, Dostavista) — канал и гость остаются нашими.
   Влияет на чекаут и юнит-экономику.
2. Какой банк даёт эквайринг (Сбер / Т-Банк / Альфа / ...) — от этого зависит
   API-адаптер и поддержка СБП.
3. Меню ведём целиком в iiko или отдельное «внешнее меню» iikoWeb
   (для веб-названий, описаний и фото)?
4. Домен и название для прода.
