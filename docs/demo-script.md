# Сценарий демо для заказчика

Цель показа: (1) убедить, что основа сайта уже работает, (2) собрать
пожелания, (3) получить недостающие входные данные. Всё демо идёт на
мок-данных iiko — реальное меню подключится ключом без переделок.

Подготовка: `make dev-backend` + `make dev-frontend`, открыть
`localhost:5173` **с телефона или в мобильном режиме браузера** — сайт
mobile-first, так он выглядит правильно. Для эффекта реального времени
держать открытыми два окна.

## Маршрут показа (~15 минут)

1. **Главная** → «Смотреть меню». Подчеркнуть: хиты и витрина управляются
   тегами из iiko — персонал отмечает блюдо, сайт перестраивается сам.
2. **Меню**: поиск, фильтры «острое»/«веган», исключение аллергенов.
   Подчеркнуть: КБЖУ и аллергены — из карточек блюд в iiko, ничего не
   дублируется.
3. **Эффект стоп-листа** (вау-момент №1): во втором окне отправить вебхук
   стоп-листа — блюдо гаснет у всех мгновенно:
   `curl -X POST localhost:8000/api/webhooks/iiko -H 'Content-Type: application/json' -d '[{"eventType":"StopListUpdate","eventInfo":{"items":[{"productId":"dish-raf"}]}}]'`
4. **Чекаут доставки**: адрес «Тверская» → подсказки → зона с условиями;
   адрес «Зеленоград» → «вне зоны». Подчеркнуть: проверка ДО оплаты.
5. **Самовывоз**: «к ближайшему времени (~32 мин, с учётом загрузки
   кухни)» — время считается от очереди заказов, включая агрегаторы.
6. **Трекер** (вау-момент №2): оформить заказ, во втором окне отправить
   вебхук смены статуса — шаг на трекере переключается сам:
   `curl -X POST localhost:8000/api/webhooks/iiko -H 'Content-Type: application/json' -d '[{"eventType":"DeliveryOrderUpdate","eventInfo":{"id":"<iiko-id заказа>","status":"cooking"}}]'`
7. **Бронь**: карта зала, занятый стол серый, выбор свободного, форма.
   Подчеркнуть: схема зала рисуется из iiko — переставили столы в iiko,
   сайт перерисовался.
8. **Стол по QR** (вау-момент №3): открыть `/t/A2` на двух устройствах,
   добавить блюда с обоих — общая корзина стола обновляется у всех,
   позиции подписаны именами. Оформить — заказ ушёл «на стол».
9. **ЛК**: вход по телефону (демо-код 0000), история, «Повторить»,
   блок «Как обычно?» на главной, автоподстановка телефона в чекауте.

## Вопросы заказчику (собрать фидбек)

- Зоны доставки: сколько, границы, минимальные суммы, цена доставки?
- Самовывоз: базовое время готовности среднего заказа? (для формулы ETA)
- Бронь: длительность слота (сейчас 2 часа)? Нужна ли предоплата
  предзаказа к брони?
- Новости/акции: вести Telegram-канал (сайт подхватит сам) или форма?
- «Счастливые часы», конструктор блюд — интересно? (фаза 2–3)
- Стиль: референсы кафе/сайтов, которые нравятся (для дизайнера).

## Что попросить у заказчика (входные данные)

1. **iiko**: apiLogin (у дилера), подтверждение модулей тарифа Pro.
2. **Банк эквайринга** — название; остальное сделаем адаптером.
3. **DaData**: регистрация бесплатного аккаунта (только почта) → ключ.
4. **VPS + домен** — либо доступы, либо мы подберём (~700–1600 ₽/мес).
5. **Telegram**: создать бота у @BotFather (5 минут) → токен; рабочая
   группа персонала → уведомления о заказах и бронях уже работают.
6. **Контакт дизайнера** — передать docs/design-brief.md.
