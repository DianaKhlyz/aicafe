# Карта фич по фазам

Статусы:
- ✅ **согласовано** — делаем;
- 🤝 **требует согласования с заказчиком** — идея принята, но нужно «да» от бизнеса;
- ⚠️ **риск** — реализуемость подтверждаем на песочнице iiko (см. [open-questions.md](open-questions.md)).

Каждая фича дополнительно обсуждается перед реализацией.

## Ядро (заявленные требования, фаза 1)

| Фича | Статус | Как реализуется |
|---|---|---|
| Меню с сайта = меню iiko | ✅ | Внешнее меню iiko (`api/2/menu`): витринные названия, описания, фото, КБЖУ, аллергены редактируются персоналом в iikoWeb. Синхронизатор кэширует данные и картинки локально. Настройки отображения (порядок категорий, бейджи «хит»/«новинка», скрытие с витрины) — тонкий слой на сайте. Переопределение текстов на сайте — только опция на крайний случай |
| Активные стоп-листы | ✅ | Вебхук `StopListUpdate` → SSE всем открытым клиентам (блюдо гаснет за секунды) + перегенерация статики |
| Корзина | ✅ | Единая для всех режимов (доставка / самовывоз / стол) |
| Доставка на сайте | ✅ | `createDelivery` в iiko; своей службы доставки нет |
| Зоны доставки | ✅ | DaData-подсказки → координаты → point-in-polygon на нашем сервере + дублирующая проверка iiko. Карта зон на странице «Доставка» |
| Самовывоз ко времени / к ближайшему | ✅ ⚠️ | Гибкий расчёт ETA от загрузки кухни: iiko не отдаёт готовую метрику, считаем сами — активные заказы через API/вебхуки (включая заказы агрегаторов — они тоже в iiko) + нормативное время приготовления по категориям. Формула: `ETA = базовое время + надбавка за очередь`. Риск: состав доступных данных о кухне проверить на песочнице |
| Бронь столов с интерактивной картой зала | ✅ ⚠️ | `reserve/available_restaurant_sections` (схема залов, столы, координаты) + вебхук `ReserveUpdate` → живая карта занятости и слоты времени. Организационное требование: хостес ведёт брони в iiko. Риск: проверить формат схемы зала на реальных данных |
| Агрегаторы (Яндекс Еда и др.) | ✅ | Подключаются к iiko напрямую, сайт не участвует. Их заказы автоматически учитываются в нашем расчёте загрузки кухни |
| QR-меню за столом | ✅ | Режим сайта `/t/{tableCode}` (коды столов из iiko): то же меню, та же корзина, чекаут «за столом», заказ в iiko с номером стола |
| Оплата по QR / эквайринг | ✅ ⚠️ | Интерфейс `PaymentProvider` с заглушкой, банк уточнит заказчик. СБП-deeplink + форма карты. Чек 54-ФЗ — на эквайринге, в iiko тип оплаты «онлайн». Риск: несколько внешних платежей на один заказ (для split) |
| Чекаут | ✅ | Три ветки: доставка / самовывоз ко времени / за столом. Гостевой чекаут всегда доступен |

## Фаза 1 — дополнительные фичи (почти бесплатны при нашей архитектуре)

| # | Фича | Статус | Детали |
|---|---|---|---|
| 1 | **Общая корзина стола / групповой заказ по ссылке** | ✅ | Компания сканирует один QR — все добавляют блюда в общую корзину со своих телефонов в реальном времени (SSE уже есть). Та же механика — «скинь ссылку коллегам» для офисной доставки. Плюс разделение заказа на части для раздельной оплаты — официант видит разделение (в iiko как отдельные платежи; опционально веб-вью «стол → кто что оплатил» для персонала, обсудим при реализации) |
| 2 | **Живой трекер заказа** | ✅ | принят → готовится → в пути/готов; вебхук `DeliveryOrderUpdate` → SSE |
| 3 | **Повтор заказа в 1 клик** | ✅ | История в iiko (по телефону) + снапшот у нас. Требует авторизации — но мягкой: гостевой чекаут остаётся, после первого заказа предлагаем «сохранить историю». Работает и онлайн, и за столом («ваш прошлый заказ») |
| 4 | **Фильтры по аллергенам и КБЖУ** | ✅ | Данные уже лежат во внешнем меню iiko (аллергены, теги, энергетическая ценность) — просто вытаскиваем и делаем фильтры «без глютена / острое / веган» |

## Фаза 2 — после запуска основы

| # | Фича | Статус | Детали |
|---|---|---|---|
| 5 | **Предзаказ к брони** | 🤝 | Бронь стола + заказ блюд к времени прихода (`reserve` + `createOrder` с отложенным временем). **Только по предоплате** — чтобы гость «не исчез», а кухня не готовила в никуда. Требует согласования с заказчиком |
| 6 | **«Лучшее время для визита»** | ✅ | Тепловая карта загруженности по часам на нашей статистике заказов (как «популярные часы» в картах). Бонус: разгружает пиковые часы |
| 7 | **Оплата счёта за столом + чаевые + split** | ✅ ⚠️ | Тот же интернет-эквайринг, что и для доставки (гость уже на своём телефоне). Split по позициям («плачу за свои две») — редкая фича. Риск: несколько платежей на заказ в iiko |
| 8 | **Отзыв, привязанный к заказу** | ✅ | Триггер — вебхук закрытия заказа. Каналы (без SMS): страница трекера / экран после QR-оплаты → Telegram-бот (если привязан) → e-mail (опция). 4–5 звёзд → ссылка на отзыв в Яндекс.Картах; 1–3 → форма «что случилось» + мгновенное уведомление менеджеру в TG |
| 9 | **Telegram Mini App + бот** | ✅ | TMA = наш сайт внутри Telegram (тот же домен и сервер). Бот через webhook на наш FastAPI (без polling — нечему умирать), уведомления о статусе заказа вместо SMS. Bot API из РФ работает штатно. Вся информация по заказам всё равно сходится в iiko — TG только канал уведомлений |
| 10 | **Вызов официанта / «принести счёт»** | ✅ | Кнопки в режиме стола → уведомление персоналу (TG-группа или иной канал). При реализации рассмотреть вариант через iiko, чтобы информационная связь шла в единую точку |

## Фаза 3 — эксперименты

| # | Фича | Статус | Детали |
|---|---|---|---|
| 11 | **Лояльность iikoCard + Wallet-карты** | ✅ («делаем 200%») | Бонусы/кэшбэк/персональные акции через iikoCard (входит в Pro). Карты в **Apple Wallet** (.pkpass, нужен Apple Developer ~$99/год) и **Google Wallet** (API бесплатный): QR/штрихкод номера iikoCard, баланс обновляется пушем в карту. Самописно — вместо платных сервисов (OSMI, PassTeam). Изучить другие wallet-платформы для охвата |
| 12 | **«Счастливые часы» против списаний** | 🤝 | Автоскидки на позиции с риском списания к закрытию — через ценовые категории/акции iiko. Заказчик согласует |
| 13 | **Конструктор блюд** | 🤝 | Модификаторы iiko из коробки (соусы, размеры, «без лука»); задача в основном дизайнерская. Заказчик согласует |

  TG-канал — сайт автоматически подхватывает пост с фото в раздел новостей.

  См. [open-questions.md](open-questions.md).
